# Решения

## Диктовка

Одна кнопка на телефоне: человек говорит по-русски, текст появляется на экране сразу. Готовый текст можно поправить, скопировать или стереть.

Звук распознаётся в самом браузере. Запись на сервер не уходит. На сервер позже уходит только уже готовый текст — когда человек просит обработать идею.

## Как открыть в Chrome на Android

Микрофон включается только на защищённой странице: адрес должен начинаться с `https://`. Ссылка `http://` и открытие файла с телефона не сработают. `localhost` считается защищённым только если страница открыта на самом телефоне.

1. Выложить папку на обычный HTTPS-хостинг (отдельные заголовки COOP/COEP не нужны) и открыть адрес в Chrome.
2. Либо на компьютере, в одной сети Wi-Fi с телефоном:

```bash
python3 scripts/serve-https.py
```

Скрипт печатает адрес вида `https://192.168.x.x:8443`. Его открывают в Chrome, подтверждают предупреждение о сертификате и разрешают микрофон.

Первый запуск скачивает модель (44 МБ) и движок (около 5,5 МБ). Пока идёт загрузка, на экране есть полоса и размер. После этого диктовка работает без сети: страницу и модель держит сервис-воркер, распакованная модель остаётся в памяти браузера. Обработка идеи на сервере сеть требует.

## Почему не Web Speech API

В Chrome обычный `SpeechRecognition` / `webkitSpeechRecognition` отправляет звук на сервер. Режим `processLocally: true` запрещает сеть, но в Chrome для Android его нет (настольный Chrome — да, Android — нет). Поэтому страница его не вызывает.

Распознавание делает [vosk-browser](https://github.com/ccoreilly/vosk-browser) 0.0.8: WebAssembly в воркере, без общей памяти и без COOP/COEP. Модель `vosk-model-small-ru-0.22` (Apache 2.0) лежит в `models/` и читается только с этого же сайта.

## Ограничения распознавания

Маленькая модель рассчитана на телефон, но ошибается чаще большой: на чужих записях это примерно от 12% до 32% слов в зависимости от шума. Знаков препинания нет, слова чаще строчные. На слабом телефоне слова могут отставать на долю секунды. Первая распаковка модели после скачивания занимает заметное время. Слово «стоп» модель может расслышать неточно, поэтому рядом с голосом всегда есть кнопка «Обработай».

## Сборка в устанавливаемое приложение

Принято 14 октября 2026.

- Клиент остаётся веб-страницей и ставится на телефон как PWA: манифест, иконки, сервис-воркер, отдельное окно без адресной строки.
- Сервер: Node.js, Express, Prisma, PostgreSQL. Всё поднимается через Docker Compose. Снаружи страницу и API отдаёт Nginx.
- Вход — OAuth Mail.ru. Сессия лежит в httpOnly-куке. Идеи видит только адрес из `OWNER_EMAILS`. Чужой ящик получает отказ и не вызывает модель.
- На компьютере, когда `APP_ORIGIN` — localhost и `DEV_AUTH_BYPASS=1`, есть вход без Mail.ru. На боевом сервере этот вход выключен: телефон заходит через Mail.ru по публичному HTTPS.
- Звук по-прежнему распознаётся на телефоне. На сервер уходит текст из поля, после слов «стоп» или кнопки «Обработай».
- Модель на сервере убирает повторы, собирает одну последовательную идею, даёт ей название. В базе хранятся и исходный текст, и готовая идея: исходник нужен, если формулировку захочется переделать.
- Список идей можно смотреть и менять порядок. Поделиться — через системное меню телефона (почта и другие приложения, которые телефон сам предложит).
- Модель для суммаризации вызывается по OpenAI-совместимому API. Адрес, имя модели и ключ задаются переменными окружения, значения в репозиторий не попадают.
